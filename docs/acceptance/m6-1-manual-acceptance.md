# M6.1 验收：中控动作提醒

当前范围：本地规则 → Control 提醒 → 人工处理 → 本地回看。M6.2 OBS、M6.3 webhook 与 M7 均未实现。以下实机项目保持待执行，自动化通过不能替代实机签字。

## 快速复现（Windows / macOS 各执行）

1. 在 M6 独立工作树安装依赖后执行 `pnpm dev`。新用户默认关闭动作提醒；准备区可看到两类模板。
2. 选择示例框架、模拟音频、Fake ASR、问题样例；设置分析窗口 60 秒、间隔 15 秒。
3. 示例默认是冷却 180 秒、阶段可同时选「讲品」和「促单」，不勾讲点时直接口播链接或发券也会提醒。本步仍显式配置旧入口：启用动作提醒及推流规则，阶段「开场」、讲点「核心卖点至少提一个」、冷却 120 秒；同样启用发券规则并保存。保存后的修改从下次开始盯播生效。
4. 开始盯播，确认配置只读。约第一个完整窗后应出现推流建议；该样例当前窗有禁讲命中，不能出现发券建议。卡片包含时间、阶段、讲点和字幕证据；Stage 不显示动作信号。
5. 点击「确认已处理」，显示已确认处理及时间，没有“推流成功”或外部请求。持续满足条件不能重复弹出。
6. 切换到「讲品」，等待冷却结束，再切回「开场」，下一个合格分析窗应产生新提醒。切换阶段必须立即使旧待处理项失效。
7. 对新提醒点「忽略」，状态固定；反复点击不会产生多条处理记录。
8. 用一份无禁讲匹配的测试框架重复步骤（更换框架后需重新保存规则），确认发券提醒可出现。不能把缺少音频、final 文本或语音覆盖当成“无风险”。
9. 停止时所有待处理项失效，不因最后补算新增提醒；Control 自动回看显示信号和人工处理记录，无操作按钮。
10. 打开历史场次，再盯一场，确认旧场不能处理，新场不继承信号、冷却或阶段。

## 故障与兼容

- 新用户或关闭功能：原有 M5 采音、字幕、问题、Stage、回看正常，无动作信号。
- 改变框架 revision：提醒关闭并提示重新保存；不能自动套用旧规则。
- 备份后损坏用户目录 `action-rules.v1.json`：默认关闭提醒、显示提示，原有盯播继续。
- 在一次测试场次中模拟 `action-signals.v1.jsonl` 写失败：提醒和处理仍可使用，显示内存保留提示。当前场回看优先显示尚在内存中的完整记录。
- 打开不含附属文件的旧场次：显示「无信号记录」。附属文件损坏：仅信号区域报错，字幕与问题仍可回看。
- 采音 / ASR 降级：待处理提醒立即失效，重连后须等新的合格窗口；失败重试不修改原有问题或转写。
- Stage preload 只有阶段与字幕的读取/订阅方法；Main 拒绝 Stage、外来窗口和子框架调用 `actions:*`、设置、密钥、起停等 Control 接口。
- 重复确认幂等；不同处理状态不可覆盖；跨会话和已过期请求拒绝。

## 自动化覆盖

- `actions.test.ts`：规则、禁讲、窗口质量、冷却、重复触发、状态、配置和独立 JSONL。
- `actionSession.test.ts`：复用真实会话调度、阶段失效、降级、停止/重启、回看与只读卡片。
- `ipcRoles.test.ts`：所有注册 invoke 通道的窗口权限，包括新增 actions 通道。
- `pnpm test`、`pnpm typecheck`、`pnpm package`；M5 双窗与真环回继续使用原验收清单。

## 发布与热修

- 基线为 M5 已有独立提交，M6 使用 `codex/m6-control-signals` 和独立工作树。
- IPC 权限修复独立保存在 `codex/fix-m5-ipc-roles`，可单独合入 M5；M6 不合入主线、不发版本。
- 每轮预留约 30% 容量处理 M5 热修和回归；阻断直播的故障优先。M6 每个切片及合并前检查主线更新。
- M5 运行数据格式不变；`action-rules.v1.json` 和每场 `action-signals.v1.jsonl` 为附属文件，旧版不读取它们。
- 回退时停止当前会话，关闭动作提醒，使用已验证 M5 构建；附属文件可保留。
