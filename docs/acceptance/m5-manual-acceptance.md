> 状态：**待实机执行**。本文是执行清单和结果模板，不代表已经通过验收。
>
> 单元测试与 Fake ASR 注入不能替代本清单。不得把模拟音频、加速时钟或单元测试写成真环回结果。

## 当前代码差异（2026-10-20）

本清单保留完整退出目标，以下已知缺口不能填为通过，也不因单测通过而跳过：

- **角色权限**：Stage 组件无写控件，但共用完整 preload，Main IPC 未按发送窗口角色校验。需补只读桥和主进程角色校验后，才可通过能力隔离检查。
- **pin / dismiss**：pin 只作用于未读问题；dismiss 不会解除已有 pin。Control 没有取消 pin 按钮，§3.2 的对应步骤当前无法通过。
- **显示器**：选择只在内存中，启动预选第一项，刷新时失效 id 也可能改选第一项；不持久化。全屏模式按 bounds 摆放但仍有窗口边框。§3.4 的记忆、排练标记及无边框目标尚未完成。
- **断屏提示**：主进程已发事件，preload / Control 未订阅，用户看不到提示。
- **打开失败**：参数和屏幕校验失败会返回中文提示；异步页面加载失败没有专门处理。
- **Control 尾项**：品备注只有 IPC / 投影字段，无输入框。main 上还没有中控推流 / 发券提醒。v1.0.0 的目标是画出这层控件（PRD A5），不是留空位；触发逻辑在未合的 PR #23。
- **退出行为**：Control 点击停止不弹二次确认；活动会话关闭 Control 窗口才确认。应用级退出直接停止；macOS 关完窗口仍保留应用进程。
- **复盘再盯一场**：复盘页「再盯一场」已改为只切回盯播主屏，由主播在主屏手动开始，不再直接开播。
- **抬头屏字幕**：Stage 主体已改为实时字幕滚动区，底部保留警告条；未读问题仍通过角标和 suggestion 提示。

以上是代码核对结果；真环回、双屏、DPI 与长期稳定性仍待实机执行。对应实现见 PRD §6、SDD §22.1。

## 3. 双端同机演示

### 3.1 打开 Stage

1. 启动应用，确认 Control 显示「M5 双端」。
2. 在「抬头屏」面板选择副屏，模式选「全屏」，点击「打开抬头屏」。
3. 确认 Stage 出现在副屏，主视觉只有：当前阶段、未读角标、至多一条建议，外加健康点。
4. 确认 Stage 上看不到设置、密钥、时间轴、转写长文、讲点列表、JSONL、DevTools、GMV。
5. 确认 Control 仍能看到完整问题时间轴、转写片段、框架命中、讲点覆盖。
6. 权限隔离另验：Stage 的桥只允许读取与订阅 StageView，Main 拒绝来自 Stage 的写入及敏感读取调用。当前未实现，不能仅凭 Stage 没有按钮填为通过。

### 3.2 阶段与 pin / dismiss

1. 开始盯播（模拟音频或真实环回均可）。
2. 在 Control 点击「阶段」按钮切换阶段，确认 Stage 大字同步变化。
3. 当出现问题时，在 Control 对某条问题点击「钉上大屏」，确认 Stage 固定显示该条建议。
4. 再对另一条问题点击「钉上大屏」，确认 Stage 换钉。
5. 对被 pin 的问题点击「跳过这条」，确认 Stage 跳过该条，显示下一条未读建议；问题仍留在 Control 时间轴上，未读数不变。
6. 取消 pin 后，确认 Stage 回到自动选句。

### 3.3 空态与错态

1. 未开始盯播时打开 Stage，确认阶段位显示「未开播」，字幕区显示「字幕会显示在这里」，角标不显示数字，底部无警告条。
2. 盯播进行中、没有未读问题时，确认 Stage 显示当前阶段，角标 0，字幕区持续滚动直播字幕，底部无警告条。
3. 模拟转写不稳定（如拔掉网络或触发 degraded），确认 Stage 健康点变为「不稳定」，底部警告条显示「转写不稳定，看中控」；若已有建议则仍显示建议。
4. 会话错误时，确认 Stage 阶段位显示「盯播已停」，底部警告条显示「看中控」。

### 3.4 选屏、排练与断屏

1. **单屏排练（目标，标记待实现）**：只有一块显示器时，选择「窗口」模式打开 Stage，确认 Stage 是带标题栏、可拖动的普通窗口，不全屏，并标明「排练 · 同一块屏」。
2. **全屏不抢主屏**：选择副屏全屏，确认 Control 所在的主屏不被铺满。
3. **记住显示器（目标，待实现）**：关闭 Stage 后重新打开，确认上次选择的显示器被预选，但仍需手动点击才打开。
4. **断屏**：盯播进行中拔掉 Stage 所在显示器，确认：
   - 会话继续，Control 不中断；
   - Control 提示「抬头屏断开，盯播还在」；
   - Stage 关闭，不自动挪到主屏全屏；
   - 重新选屏后可再次打开 Stage。

### 3.5 关窗

1. **关 Stage**：点击 Stage 窗口关闭按钮或按 Esc，确认盯播继续，Control 还在。
2. **Control 停止盯播**：确认 Stage 被拆掉，Control 回到停播后台面。
3. **关 Control（会话 idle / completed / error）**：确认 Stage 先被销毁，然后应用退出。
4. **关 Control（会话 running / degraded）**：确认弹出「停止盯播并关掉抬头屏？」；点「取消」则两窗都留着；点「停止并关闭」则会话结束、Stage 被拆、应用退出。
5. **不留孤儿 Stage**：确认任何路径下都不会出现只有 Stage 没有 Control 的情况。

### 3.6 中控动作提醒

1. 确认 Control 上固定显示「内容盯播，不是 GMV 总控。」。
2. v1.0.0 目标：Control 画出推流 / 发券提醒，而不是只有空位。main 上若还没有这层控件，本条不能勾过（触发逻辑在未合的 PR #23）。没有真实触发时不造假信号。
3. 确认 Stage 上不显示推流 / 发券提醒。出站 OBS / webhook 不在本清单。

## 4. DPI 与全屏

- [ ] Windows：主屏 100% 缩放、副屏 150%（或反向）。Stage 左上角落在所选屏 bounds 内，不横跨两块屏，文字不被裁切。
- [ ] macOS：Retina 内建屏 + 非 Retina 外接屏。全屏走 `setBounds(display.bounds)`，不把 Stage 送进另一块屏的 Space，菜单栏留在主屏。
- [ ] 排练窗口落在 workArea 内，不被任务栏或 Dock 整段挡住，且 Control 仍能点到。
- [ ] 拔掉副屏后，Control 仍在，会话仍是原来的状态，Stage 不自动出现在主屏全屏上。
- [ ] Stage 失焦后仍持续更新（`backgroundThrottling: false`），建议仍是一行可读短句。
