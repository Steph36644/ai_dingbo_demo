## 1. 一句话定位

**本人自用起步、面向抖音直播间小团队的桌面 AI 盯播教练。**

引擎主路径不变：听本机正在播的直播声 → 实时转写 → 滑动窗口对照本地话术框架 → 标出语速 / 节奏 / 内容问题 → 双端呈现「讲偏了什么」。

v1.0.0 的方向：**用 OBS 类专业工具的设计逻辑重构整个视觉方案**——Control 长成信息密集的中控台，Stage 保持干净的输出大屏；同一套引擎、同一份真相源、两档信息带宽。它赋能的是讲解有没有按框架落地，不是 GMV 总控。

## 2. 版本目标与背景

v0.3.0 之后，功能骨架（双端、回看、预检、成句字幕）已可用，但界面层与专业工具差距明显，无法支撑「长时间盯播不累眼、扫一眼就定位」的使用强度：

1. **视觉语言错位**：当前是「暖色纸卡编辑部」风格（大圆角 18–22px、米色浅卡浮在深底上、硬编码颜色、无设计 token），与「直播中高强度监控工具」的心智不符。字幕卡和笔记面板是深色界面里的浅色岛，抢视线、层级混乱。
2. **信息架构缺骨架**：无状态栏、无面板（dock）体系、状态在三处冗余呈现（顶栏 pill、字幕卡 footer、Stage 健康灯各有各的样式）、反馈靠挤占布局的 banner 而非瞬态消息。
3. **控件密度与反馈弱**：左栏 260px 控件稀疏堆叠，深色区按钮无 hover / active / 焦点态，除改名输入框外全应用无快捷键。
4. **M5 已知缺口未闭合**：品备注有通道无输入框、断屏提示主进程已发渲染层没接、排练标记缺失、pin / dismiss 语义不完整、显示器选择不记忆、全屏仍有边框、Stage 加载失败无提示。Stage 通道只读已随 PR #22 合入 main，本版只做验收复验（G4 / FR-17）。

产品决策：v1.0.0 = **一次以视觉重构为主轴、顺带闭合其余 M5 已知缺口的完整性版本**。引擎、规则、ASR、JSONL、回看数据格式全部不动。交付顺序见 §9.1：原版 Brief 是底线，外观和推流 / 发券增强不能挤掉它。

## 4. 视觉方案：中控台设计语言

> 主轴：把 OBS Studio 这类「直播中专业控制台」的设计逻辑，映射到盯播域。**只借鉴结构与密度，不照搬直播软件的功能隐喻**（不做多画面宫格、不做推流按钮、不做音轨推子）。
>
> 完整设计依据（为什么对标 OBS、借什么不借什么、为何必须先 token 化、视觉验收自检四问）见 [`docs/design/visual-system.md`](../design/visual-system.md)；结构参考图（新旧对照 / Control 三 dock / Stage 大屏 / 落地顺序）见 [`visual-system.html`](../design/visual-system.html)。节内只写规格，不重复论证。

### 4.1 设计原则（OBS 逻辑 → 盯播映射）

| OBS 概念 | 盯播对应 | 产品理由（蕴含需求逻辑） |
|----------|----------|--------------------------|
| 输出窗（Projector）无菜单、无设置 | **Stage 抬头大屏**：只有阶段、角标、至多一条建议、字幕流、健康点 | 主播 / 助播在镜头前只吃短信号（§3.4 US-1），任何多余控件都会抢注意力 |
| 主窗多 dock 工作区 | **Control 中控台**：左中右三个 dock 区 + 顶部工作区切换 + 底部状态栏 | 中控要在同一屏内完成「来源管理 → 监视 → 处置」闭环（US-2），信息密集、一屏不换页 |
| 场景（Scenes）列表 | **阶段列表**（框架 `stages[]`）：当前阶段高亮，点选即切 | 阶段是本场讲解的「节目单」，中控切换、大屏跟随；不是幻灯片翻页 |
| 来源（Sources）清单 + 属性面板 | **来源与预检 dock**：音源、ASR 引擎以列表呈现，带状态图标；选中项下方展开详情与预检结果 | 开播前要一眼确认「听谁的、谁转写、健康吗」，失败不可开始（凭据门禁沿用） |
| 混音器（Mixer）电平 | **音量指示**：分段 meter + 数字读数，静音 / 无信号给红灰提示 | 环回「到底有没有声音」是开播第一疑问；不做分贝刻度与推子，不造假精度 |
| 预览监视器 | **字幕监视器**：Control 中央的成句字幕大区 | 中控要看可解释的转写上下文（US-2），它是问题时间轴的证据面 |
| 底部状态栏 | **常驻状态栏**：状态、采音时长、音源、ASR、落盘、未读、固定声明 | 长时间盯播中，关键健康信息必须永远可见、不随滚动消失；三处冗余状态收敛到这一处 |
| 转场 / 控制按钮组 | **开始 / 停止主控**：预检内联 + 阻断原因红字 + 主按钮 | 高频核心动作，位置固定、状态明确、可盲操 |
| 深色高密度、小圆角、细描边 | 全站统一深色 token 体系（§4.2） | 直播环境弱光、长时间注视；浅色纸卡废除，消除「浅色岛」层级混乱 |

明确不借鉴：Multiview 宫格、推流 / 录制按钮、音轨推子与分贝刻度、场景转场动画、插件系统。

### 4.2 设计 token（全站唯一颜色与规格来源）

实现层以 CSS 自定义属性落成唯一 token 表，禁止再出现硬编码色值（现状 `#f2c14e` 等散落 10+ 处、stage.css 与 styles.css 绿色不一致，全部收敛）。

| Token | 值 | 用途 |
|-------|-----|------|
| `--bg-0` | `#0e1114` | 窗口底 |
| `--bg-1` | `#15191d` | dock 面板底 |
| `--bg-2` | `#1c2228` | 输入框 / 控件底 |
| `--bg-3` | `#242c33` | hover / 选中底 |
| `--border-0` | `#2a323a` | 描边、分隔线 |
| `--text-0` | `#e8edf2` | 主文字 |
| `--text-1` | `#9aa7b2` | 次文字 |
| `--text-2` | `#5f6b76` | 弱文字 / 占位 |
| `--accent` | `#4f8cff` | 选择、焦点、链接、选中左缘 |
| `--ok` | `#3fbf6f` | 正常、已讲、健康 |
| `--warn` | `#e6b34d` | 警告、进行中、未讲 |
| `--crit` | `#e05b4d` | 严重、触雷、live 灯 |
| 圆角 | 面板 6px，控件 4px | 取代现 18–22px 大圆角 |
| 字体 | `"Inter","Segoe UI","PingFang SC","Noto Sans SC","Microsoft YaHei"`；界面基准 13px，辅助 12px，数字一律 `tabular-nums` | |
| 字幕字号 | 监视器当前句 22–26px、历史 15–17px；Stage 当前句 32–40px、历史 24–28px、阶段大字 56–72px | 按观看距离定 |
| 间距 | 4 / 8 / 12 / 16 栅格；列表行高 28px | 高密度 |
| 动效 | 100–160ms 过渡；仅 live 灯允许呼吸动画 | 反馈即时，不做装饰动画 |
| 对比度 | 文字对底色 ≥ 4.5:1（WCAG AA） | 弱光环境可读 |

主题策略：v1.0.0 **仅深色单主题**（[Assumption, TBD]：不做浅色主题切换）。语义色只用于状态，不用于装饰。

布局规则：

1. 三栏 grid（约 264px / 自适应 / 320–360px），面板可整体折叠为窄条（沿用现笔记折叠交互，推广到全部右 dock），折叠状态记入本机。
2. 每个 dock 是统一结构的面板：13px 小标题栏（可含操作按钮）+ 内容区。标题栏点击折叠 / 展开。
3. 工作区切换：**盯播 / 回看 / 设置**三个平级工作区，「场次」不再是从盯播页斜切的临时模式——点「回看」进入回看工作区，骨架与盯播一致（左 dock = 场次目录，中央 = 只读字幕监视器 + 只读问题 dock）。锁定（盯播中）时「回看」「设置」仍可进，但回看工作区提示「盯播进行中，目录不含本场」。
4. 底部状态栏常驻所有工作区，字段见 FR-14。

### 4.4 Stage 抬头大屏布局

```
┌──────────────────────────────────────────────┐
│ ● 健康 [排练 · 同一块屏]        未读 ⓷        │
│                                              │
│                    讲品                      │

│  ┌────────────────────────────────────────┐  │
│  │        ……前两句（渐隐，居中）            │  │
│  │                                        │  │
│  │        当前句全亮（居中）                │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

- 深底 `#0a0d10`（比 Control 更深一档），无任何可操作控件。
- **五要素位置固定不变**：阶段大字、建议条、字幕区、未读角标、健康点（排练标记常驻顶栏）。直播中扫一眼即可完成定位。
- **阶段大字与建议条上移**，占画面上部约 1/3，不与字幕区争视觉重心。
- 建议条：单条卡片，左缘 4px 语义色（按严重度），字号 ≥ 28px。
- **字幕区为独立底色容器**：`--bg-1` 底 + `--border-0` 描边 + 6px 圆角，与阶段 / 建议做视觉分隔；跨满可用宽度。
- 字幕文字**水平居中**：当前句全亮，历史 1–3 行渐隐（越早越淡），与当前句同容器。
- 字幕区**固定高度**：超出时容器内上滚，当前句始终在最底行；不随内容长高挤压上方阶段 / 建议。
- 排练标记：窗口 / 单屏模式在顶栏健康点右侧显示「排练 · 同一块屏」小胶囊；全屏模式不显示。

### 4.5 组件规范

| 组件 | 规格 |
|------|------|
| 按钮 | primary（`--accent` 底白字）/ danger（`--crit` 底，停止用）/ ghost（透明描边）；全部有 hover（`--bg-3`）、active（加深 8%）、focus-visible（2px `--accent` 外环）；禁用 `opacity .45` + `not-allowed` |

## 6. 功能需求

> 全部 FR 的**行为语义**以 PRD v0.3.0 §5 / §6 为准，此处只写 v1.0.0 新口径与承载变化；未提到的行为一律「与 v0.3.0 相同」。

### FR-01 设计 token 与应用骨架

- **触发**：应用任意界面渲染。
- **规则**：全站颜色、圆角、字号、间距、动效只取自 §4.2 token 表；删除全部硬编码色值；浅色纸卡（字幕卡、笔记面板）转为同主题深色面板，字幕区以 `--bg-2` 底 + 更大字号区分，不再用明度反差造层级。
- **结果**：任意两个界面同源 token；stage.css 与 styles.css 的绿色不一致消除。
- **验收锚点**：代码中不再出现 `#f2c14e` / `#f6f1e6` 等旧色值。

### FR-02 顶栏与工作区切换

- **组成**：品牌区（live 灯 + 「AI盯播」）、工作区 tab（盯播 / 回看 / 设置）、会话状态 pill、未读角标 pill。
- **规则**：状态 pill 是全应用状态的第一呈现；回看工作区激活时状态 pill 右侧显示「JSONL 只读」标记；盯播中进入其他工作区不中断会话（对应旧「关 Stage 不停会话」精神——切工作区更不停）。
- **结果**：「场次」伪 tab 消失，回看成为正式工作区。

### FR-03 来源与预检 dock（左）

- **组成**：音源列表（系统环回 / 模拟音频 / 抖音直播流）、ASR 引擎列表（Fake / FunASR / 讯飞），每项带状态图标（就绪绿 / 检查中黄 / 失败红 / 未选灰）；选中项下方展开详情（设备列表、注入文稿选择、直播流 URL 输入、预检结果、阻断原因）。
- **抖音直播流口径**：只接受 `https://live.douyin.com/<6–20 位数字房间号>` 形式的链接（允许省略协议、忽略 query / hash，其余域名与路径一律不接受）。开始前校验，不合法时主按钮不可用并给出原因；开始后不可切换音源。直播画面默认隐藏，用户可随时点「显示 / 隐藏直播画面」查看，用于完成登录、确认是否在播。30 秒内没有收到直播音频判为失败，提示可能未开播 / 需要登录 / 该直播间不支持网页播放，并自动显示画面供排查。
- **明确不做**：开播监测、抓取抖音私有接口、其他平台直播流、在直播流链路中做录制或下载。
- **规则**：选择行为与 v0.3.0 相同（开始后不可换源 / 换 ASR）；预检失败时主按钮不可用并显示原因；「重新检查」按钮保留。
- **交互**：列表行点击即选中，详情就地展开（OBS 来源→属性面板逻辑）。

### FR-04 采音控制（左）

- **组成**：分段音量 meter + 数字读数（0–100）、开始 / 停止主按钮。
- **规则**：meter 分段色阶：底 `--bg-2`，正常 `--ok`，过载段 `--crit`；无信号 5 秒以上 meter 区显示「无信号」灰字（不造假数值）。开始 / 停止的确认、门禁、降级行为与 v0.3.0 相同。
- **明确不做**：分贝刻度、推子、静音按钮。

### FR-05 字幕监视器（中央上）

- **组成**：标题栏（「字幕监视器」+ 会话时钟 + 阶段副标题）、成句字幕滚动区、常驻 footer（落盘提示）。
- **规则**：成句 / 软切 / 周期性标点口径与 v0.3.0 §5.2 第 7 条一致；当前句 `--text-0` 大字，partial 带 `--warn` 光标；自动跟随与上滚暂停沿用现有 `useCaptionFollow` 逻辑；banner 仅保留常驻阻断类（见 §4.5），降级重连等瞬态转 toast。
- **空态**：一句引导 + CTA（「选择音源后开始盯播」）。

### FR-06 问题时间轴 dock（中央下左）

- **组成**：标题栏（「问题」+ 未读 badge + 全部标为已读）、类型 / 严重度过滤器、问题卡列表、证据抽屉。
- **新口径**：
  - 问题卡、过滤器、指纹聚合、历次证据展开与 v0.3.0 完全一致；
  - 新增「**取消钉住**」按钮：存在 pin 时出现在 dock 标题栏（替代原「钉上大屏」按钮的取反态），点击清空 pin，Stage 回到自动选句；
  - **dismiss 修正**：dismiss 对**包括被 pin 在内的**任意问题生效；若 dismiss 的是被 pin 的那条，则同时解除 pin，Stage 显示下一条未读（若无可显示则留空，不编一句）。dismiss 仍不把问题标已读。
- **只读态**：回看工作区内本 dock 只读，操作按钮隐藏，显示「JSONL 只读」。

### FR-07 讲点覆盖 dock（中央下右）

- 行为与 v0.3.0 相同（`must_say` 已讲 / 未讲、时间、段数）。视觉：已讲 `--ok`、未讲 `--warn`，计数徽标进标题栏。窄屏折叠行为见 FR-19。

### FR-08 阶段列表（右上）

- **组成**：框架 `stages[]` 列表，行式呈现（OBS 场景列表逻辑），当前阶段 `--accent` 左缘 + 高亮。
- **规则**：点选即切换（盯播中可点）；无 stages 时列表区显示「当前框架没有阶段，大屏显示『直播中』」，两端阶段位显示「直播中」；换阶段不重置未读、不新开分析。显示文案与置灰规则与 v0.3.0 相同。

### FR-09 抬头屏输出 dock（右上）

- **组成**：显示器列表（含主屏 / 副屏标签、宽高、缩放）、模式选择（窗口 / 全屏）、打开 / 关闭 / 刷新按钮、错误短句、**Stage 状态镜像行**（阶段 + 未读数 + 当前建议首句，文本级，不做画面缩略）。
- **新口径**：
  - 全屏模式打开的 Stage 无窗口边框，真铺满所选屏（仍禁止铺 Control 所在屏）；
  - 窗口模式的排练标记由 Stage 端显示（FR-15）；
  - 断屏行为与 v0.3.0 相同（Stage 关闭、会话继续、不挪屏），提示经 FR-16 toast 呈现「抬头屏断开，盯播还在」；
  - 显示器选择持久化见 FR-18。
- **明确不做**：画面缩略 / 镜像预览（后置）。

### FR-10 品备注（右上）

- **组成**：多行文本输入框（本场排品 / 机制备注），字数上限 500。
- **规则**：内容仅本场内存 + 经既有 `stage:set` 通道进投影；停止盯播即清空；不进 JSONL、不进回看、不进 Stage 显示；可空。边界声明沿用：这里不是 GMV 面板，输入框上方固定小字「仅本场备注，不读任何平台数据」。

### FR-11 直播笔记（右下，实验）

### FR-12 回看工作区

- **骨架**：左 dock = 场次目录（列表化、行高 28px、改名沿用 Enter / Esc）；中央上 = 只读字幕监视器；中央下 = 只读问题 dock（含历次证据展开）。
- **规则**：数据、改名、200 场截断、「再盯一场」不删文件等行为与 v0.3.0 完全一致；顶部工具条（返回盯播 / 再盯一场）迁入工作区顶栏。
- **空态**：目录空时「还没有已落盘的历史场次」，CTA「去开始第一场」。

### FR-13 设置工作区

- 现有全部设置项（窗口 / 间隔、讯飞凭据、废弃密钥清除、当前配置摘要）迁入工作区骨架，分节卡呈现；表单校验、提交即清空密码框、隐私说明文案不变。视觉统一 token。

### FR-14 底部状态栏

- **字段（左→右）**：会话状态（STATE_LABEL）、采音时长（mm:ss，盯播中走表）、音源名、ASR 引擎名、落盘指示（「已落盘」/「落盘失败」/盯播中「—」）、未读数。

- **规则**：常驻所有工作区；状态字段与顶栏 pill 同源（同一状态机的两个读数），除此之外不再有第三处状态文字——字幕卡 footer 的状态行移除。Stage 健康点是 Stage 端的独立读数，不算冗余。

### FR-15 Stage 大屏 v1

- 视觉按 §4.4（阶段与建议上移、字幕区独立底色容器、水平居中）；行为新增三条：
  - **排练标记**：窗口 / 单屏模式时顶栏健康点右侧显示「排练 · 同一块屏」小胶囊；全屏不显示；
  - **字幕区**：固定高度容器内上滚，当前句始终在最底行，不挤压上方阶段与建议；
  - **加载失败**：Stage 页面异步加载失败时，显示「抬头屏打开失败，盯播还在」短句 + Control 端 toast，不创建空白窗。

### FR-16 瞬态消息与确认（横切）

- **Toast**：承接断屏提示、落盘失败、回看打开失败、Stage 加载失败、显示器失效回退等瞬态事件；右下角、语义左缘、5 秒自动消失（错误类手动关）、最多 3 条。
- **模态确认**：关 Control 停播确认、清空笔记、清除凭据；文案沿用现有中文短句。
- **替代关系**：现有降级重连 / 停止提醒 / 断屏等一次性 banner 全部转 toast；凭据未配、框架错误等常驻阻断保留为内联 banner。

### FR-17 Stage 通道只读边界（安全）

- **现状（已合 main，PR #22）**：Stage 进程参数 `--dingbo-surface=stage`。该窗 preload 只暴露 `getStageState`、`getStageTranscript`、`onStagePush`、`onStageTranscript`。Main 的 invoke 只接受 Control 窗口；Stage 仅可调用 `stage:get-state` 与 `stage:get-transcript`，其余 invoke 拒绝（「当前窗口无权调用该操作。」）。`audio:chunk` 与 `audio:captureFailed` 非 Control 直接丢弃。
- **本版口径**：不重做这层隔离。视觉重构不得把写通道重新暴露给 Stage。
- **验收锚点（复验，不是新实现）**：Stage 窗口内触发任何写通道均被拒绝且无副作用；Control 行为不受影响。G1–G3、G5–G9 不因本条视为已完成。

### FR-18 显示器选择持久化

- **规则**：记住上次显示器选择（按系统显示器标识）与模式；下次打开抬头屏 dock 时预填；所选显示器不在当前列表时回退第一项并 toast 提示「上次使用的抬头屏未连接，已改选主屏」；不自动打开 Stage。

### FR-19 可访问性与响应式

- 全部可交互元素有 focus-visible 环（token 化）；hover / active 全覆盖。
- 断点行为：≤1400px 右 dock 收窄；≤1240px 覆盖 dock 折叠为窄条（替代现状直接隐藏）；≤900px 单列堆叠，顺序：字幕监视器 → 问题 → 控制 → 覆盖 → 笔记。
- Stage 端 1200 / 800px 两档缩放保留，字号随断点降档。

### 7.2 问题与建议规则（v1.0.0 修正口径）

- 自动选句：未读问题里 `critical` > `warning` > `info`，同档取 `lastSeenAtMs` 更新者；无未读且无 pin 时不显示。
- pin：同时一条，盖过自动选句；对未读问题发起；新增取消钉住；换钉 = 再 pin 另一条。
- dismiss：对任意未读问题生效（含被 pin 的，见 FR-06）；不标已读；只影响 Stage 显示。
- 已读：仍走现有已读操作；pin / dismiss / 已读均只活在本场内存。
- Stage 建议句只用规则模板，不调 LLM。

### 12.2 方向（后续才做）

1. **关键词继续当兜底 / 证据。** 子串命中留下，用来解释「为什么算讲过」。
2. **上意图识别，升级 coverage。** 先判断口播是在讲哪一件必讲的事，再用这个结果更新覆盖；升级后的 coverage 再喂 M6 提醒入口（演示依赖 PR #23 草稿，未合 main）。不另起一套入口。本版不实现。
3. **优先服务发券等动作信号。** 先对齐「该发券了 / 该推流了」，再考虑铺到一般必讲勾选。
4. **M4 问题卡先不动。** 问题卡的警告、文案、严重度保持现状，不进这条升级。

本版不动：引擎、规则、ASR、JSONL、M6 出站（OBS / webhook）、M7、问题卡。

## 13. 旁路补充：SenseVoice 探针（v1.x，未交付）

**状态：探针中。** 不进 v1.0.0 的 P0–P2，不进 §8 验收，不打 tag，不复制 `versions/`。字幕 ASR 仍是 FunASR 或讯飞 RTASR。本节只列探针阶段的待办，不把旁路写成已上线。

拍板（2026-10-21）：第一版旁路同时要情绪和音频事件（笑、音乐等），不先做纯情绪。下一步只做探针：量延迟和 CPU，定窗口，定标签枚举。测量表与通过线在 [ADR-018](../adr/ADR-018-sensevoice-bypass.md) 和 [`docs/research/sensevoice-probe.md`](../research/sensevoice-probe.md)。数字未测，一律 `[TODO: 探针实测]`。

提猫（Electron + SenseVoice）只作灵感，见竞品摘要。不把它的用法搬成盯播字幕。

### 13.1 Must（探针阶段）

1. 先写完并填写探针，再决定要不要做 sidecar。本阶段不改 `src/`。
2. 同一次探针覆盖情绪和音频事件。
3. 主链保持：PCM → FunASR 或讯飞 → 字幕 / 规则 / 动作提醒。
4. 旁路读同一份 PCM 的固定窗。失败时主链继续，用户看不到旁路报错。
5. 不驱动推流 / 发券。
6. 抬头屏保持干净。探针阶段也不在中控画灯条。

### 13.2 Should（探针阶段）

1. 窗口在 3–5 秒里选，主候选 4 秒窗、2 秒 hop，并和相邻档对比。最终档由实测决定。
2. Windows 必测。有 Mac 则同一批 PCM 另记一列；没有 Mac 不否决 Windows 结论。
3. 探针日志单独成文件。不改现有 `session.jsonl` 的行类型。
4. 灯条 / 徽章和回看筛选只写成后续形状：中控轻提示，回看以后可按笑声、音乐、情绪过滤。探针通过之前不做。

### 13.3 Won't（探针阶段）

1. 不替换 FunASR / 讯飞，不用 SenseVoice 出直播字幕。
2. 不上抬头屏。
3. 不进规则引擎，不挂钩动作提醒。
4. 不宣称已经交付，不把空的实测表写成性能结论。
5. 不做说话人分离，不补主路径声学语调。

门槛通过之后，才允许另开 sidecar 的实现设计。那个设计仍然不能改主链字幕，也不能在第一版用旁路事件去推流或发券。
