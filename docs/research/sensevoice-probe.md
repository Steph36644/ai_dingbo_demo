# SenseVoice 旁路探针清单

状态：未跑。全部实测格填写前保持 `[TODO: 探针实测]`。

决策与门槛：[`docs/adr/ADR-018-sensevoice-bypass.md`](../adr/ADR-018-sensevoice-bypass.md)。本文只规定测什么、记什么、怎样才允许开始写 sidecar。不新增产品代码，不规定 WebSocket 协议。

日期：2026-10-21。通过与否由填完的表决定，不由上游 README 的速度对比决定。

## 1. 测什么

旁路读 16 kHz、单声道、S16LE 的 PCM，按 ADR-018 §5 的窗切段，同时记下情绪和音频事件。字幕主链不改。

必测平台：**Windows**。这是门槛所在的平台。

可选平台：**macOS**。有机器就用同一批 PCM 再跑一列。没有 Mac 结果时，Windows 结论仍然有效，只在文末把「Mac 未测」记为平台风险。

不要在这次探针里把模型装进 Electron，也不要改 FunASR sidecar。

| 检查点 | `iic/SenseVoiceSmall` 或 `FunAudioLLM/SenseVoiceSmall` 或其他。权重放本机，不进 git | 见 §3 |
| 运行时 | FunASR PyTorch、`funasr-onnx` 或其他。不在本文锁定 | 见 §3 |
| 主链对照 | 至少有一轮：同一台 Windows 上，FunASR 流式会话（或已加载的 `paraformer-zh-streaming`）在跑，旁路脚本同时跑主候选窗。脚本不挂进应用 | 是否做了：`[TODO: 探针实测]` |

长录音用来填 §5。短片段用来填 §6。两套都要有，不能只用其中一套宣布通过。

切窗规则与 ADR-018 相同：最多 1 个正在推理的窗 + 1 个等待窗；等待槽满了就丢掉更旧的等待窗。用壁钟判断「下一 hop 到了但上一窗还没结束」即计一次丢弃。不要把丢弃的窗排进更长的队列再补跑，否则丢窗率会被测成 0。

延迟的起点是窗的结束时刻（这段音频在录音时间轴上已经齐），终点是标签返回。不要把切窗之前的采集时间算进去，也不要用模型自报的 RTF 代替这段壁钟。

## 6. 耳标抽检

跑模型之前先耳标。情绪和事件分两张表，都要做。样本不够就保持未测，不要用模型输出反标。

### 6.1 音频事件

至少 10 条：笑声 ≥ 3，音乐或明显 BGM ≥ 3，普通口播 ≥ 4。有掌声就加进去，不强制。

判定按窗多数标签，映射用 ADR-018 §6。普通口播上出现 `speech` 算对；把纯口播标成 `laughter` 或 `bgm` 算错。

## 8. 怎样算可以写 sidecar

同时满足才算通过。通过之后才允许另开实现 PR。本文填完不等于已经通过。

1. §3 写明检查点、运行时，且进程独立于 FunASR。
2. §5.1 至少一档（优先看 A，不行再看 B/C/D）在「旁边有 FunASR」的条件下：p95 ≤ 该档 hop，旁路 CPU 平均 ≤ 100，丢窗率 ≤ 5%，整机没有连续 30 秒 ≥ 90%。
3. 没有一档达到第 2 条，但有一档落在 ADR-018 的中间地带（p95 ≤ 2 × hop，丢窗率 ≤ 20%），并且换 hop 后达到第 2 条：有条件通过，sidecar 设计必须锁定那一档窗。
4. §6.1 ≥ 8/10 且 §6.2 ≥ 8/12。
5. §7 三行都符合期望。
6. 主链仍然是 FunASR 或讯飞。方案里没有「改用 SenseVoice 出字幕」。

不通过，停在本清单：

- 只有事件过线、情绪没过线，或相反。2026-10-21 拍板的是两样一起做。缺一路就把决策交回产品，不在清单里改成只做一路。
- p95 > 2 × hop，或丢窗率 > 20%，或旁路 CPU 平均 > 150。
- 静默失败任何一条不成立。
- 数字仍是 `[TODO: 探针实测]`。空表不能算通过。

通过之后仍然不做的事：抬头屏提示、用事件驱动推流 / 发券、修改 `session.jsonl` 行类型、把本表的空数字写成已上线能力。
